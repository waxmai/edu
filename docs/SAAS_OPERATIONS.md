# SaaS 运营治理说明

## 当前定位

本项目正在从“受控试运营交付版”升级为“多客户、多机构、长期稳定收费”的正式 SaaS 版本。

当前已经落地的治理能力包括：

- 平台 / 机构 / 校区 / 教师四层角色边界
- 套餐与订阅状态展示
- 平台续费跟进台
- 平台恢复失败告警查询页与趋势聚合
- 机构侧设置中心 `/org/settings`，支持时区、品牌、通知邮箱、安全策略与运营备注维护
- 关键写链路订阅状态保护
- 账号数 / 校区数配额限制
- 基础审计、告警与日志保留收口

## 平台侧运营视角

平台管理员当前应重点关注以下页面：

1. `/dashboard`
   - 平台概览
   - 高风险机构
   - 账号 / 校区总体规模
2. `/platform/subscriptions`
   - 续费跟进台
   - 跟进负责人负载
   - 试用转化 / 待催续费 / 已过期待恢复
3. `/platform/tenants`
   - 机构与基础套餐信息
4. `/platform/campuses`
   - 校区结构与启停状态
5. `/platform/recovery-alerts`
   - 恢复投递失败排查
6. `/platform/audit-logs`
   - 关键操作审计

## 当前套餐治理口径

后端已对以下能力做强约束：

- `subscriptionStatus=expired/past_due/suspended` 时，关键写操作受限
- `max_users` 达上限时，禁止继续新增账号
- `max_campuses` 达上限时，禁止继续新增校区

已纳入订阅保护的关键写链路：

- 新增学员
- 新增课程
- 新增课时包
- 新增缴费
- 新增排课
- 新增调补课记录
- 新增校区

## 仍建议继续演进的方向

### P2，继续产品化
- 套餐能力中心化配置
- 租户级功能开关
- 更多运营总览指标
- 更多恢复 provider
- 更细粒度 permission points

### P3，继续 SaaS 化
- 自动续费或账单体系
- 多品牌 / 多域名支持
- 更系统的安全合规基线
- 更强的数据归档与分析链路
