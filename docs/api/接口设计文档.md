# 接口设计文档

## 1. 文档说明

本文档基于《个人教培排课、课时与收费管理系统 PRD》编写，面向前后端联调、接口开发与测试使用。

接口风格建议：
- 协议：HTTP/HTTPS
- 风格：RESTful
- 数据格式：JSON
- 字符编码：UTF-8
- 认证方式：Token / JWT

接口统一前缀建议：`/api/v1`

---

## 2. 通用规范

### 2.1 请求头

```http
Content-Type: application/json
Authorization: Bearer {token}
```

### 2.2 通用响应结构

```json
{
  "code": 0,
  "message": "success",
  "data": {}
}
```

### 2.3 响应码建议

| code | 说明 |
| --- | --- |
| 0 | 成功 |
| 400 | 参数错误 |
| 401 | 未登录或登录失效 |
| 403 | 无权限 |
| 404 | 数据不存在 |
| 409 | 业务冲突，例如排课冲突 |
| 500 | 系统异常 |

## 4. 学员管理接口

> 当前后端已实现并验证通过的实际路由如下：
> - `POST /api/v1/student`
> - `GET /api/v1/students`
> - `GET /api/v1/student/{id}`
> - `PUT /api/v1/student/{id}`
> - `DELETE /api/v1/student/{id}`

## 4.1 学员列表

`GET /api/v1/students`

当前实现：无查询参数，直接返回全量学员列表。

当前返回字段：
- id
- studentName
- gender
- grade
- phone
- parentName
- parentPhone
- subject
- teachingType
- status
- remark
- createdAt
- updatedAt

---

## 4.2 新增学员

`POST /api/v1/student`

请求参数示例：

```json
{
  "studentName": "张三",
  "gender": "male",
  "grade": "初二",
  "phone": "10000001111",
  "parentName": "张先生",
  "parentPhone": "10000001112",
  "subject": "数学",
  "teachingType": "one_to_one",
  "status": "active",
  "remark": "基础较弱"
}
```

当前必填字段：
- studentName
- subject
- teachingType

成功返回示例：

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "id": 1
  }
}
```

---

## 4.3 学员详情

`GET /api/v1/student/{id}`

当前返回内容为学员基础信息，不包含课时包、缴费记录、上课记录、调补课记录等聚合数据。

---

## 4.4 修改学员

`PUT /api/v1/student/{id}`

当前支持更新字段：
- studentName
- subject
- teachingType
- gender
- grade
- phone
- parentName
- parentPhone
- status
- remark

成功返回示例：

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "rows_affected": 1
  }
}
```

---

## 4.5 删除学员

`DELETE /api/v1/student/{id}`

当前实现为物理删除。

成功返回示例：

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "rows_affected": 1
  }
}
```

业务规则建议：
- 若已有排课、课时包或缴费记录，原则上不允许物理删除，建议后续改为逻辑删除或改状态

## 5.4 新增排课

`POST /api/v1/schedules`

请求参数示例：

```json
{
  "studentId": 1,
  "courseId": 1,
  "teacherId": 2,
  "lessonPackageId": 1,
  "classDate": "2026-05-08",
  "startTime": "2026-05-08 14:00:00",
  "endTime": "2026-05-08 16:00:00",
  "classroom": "线上腾讯会议",
  "remark": "首次课程"
}
```

### 业务校验
- 学员不能为空
- 教师不能为空
- 开始时间必须早于结束时间
- 教师时间冲突校验
- 学员时间冲突校验
- 关联课时包未生效时应提示风险

### 冲突返回示例

```json
{
  "code": 409,
  "message": "当前时间段存在排课冲突",
  "data": {
    "teacherConflict": true,
    "studentConflict": false
  }
}
```

---

## 6. 调课、请假、补课管理接口

## 6.1 请假登记

`POST /api/v1/schedules/{id}/leave`

请求参数：

```json
{
  "reason": "学生有事请假"
}
```

处理逻辑：
- 原课程状态更新为 `leave`
- 自动生成待补课记录

---

## 6.2 调课处理

`POST /api/v1/schedules/{id}/reschedule`

请求参数示例：

```json
{
  "reason": "双方时间调整",
  "newClassDate": "2026-05-10",
  "newStartTime": "2026-05-10 15:00:00",
  "newEndTime": "2026-05-10 17:00:00",
  "classroom": "线下教室A"
}
```

处理逻辑：
- 保留原课程记录
- 原记录状态更新为 `rescheduled`
- 创建新排课记录
- 建立调课关联记录

---

## 11. 接口安全与异常处理建议

### 11.1 安全建议
- 所有业务接口默认需要登录
- 管理员和教师需进行角色鉴权
- 高风险操作要记录日志
- 对学员手机号、家长电话等敏感字段可做脱敏返回

### 11.2 异常处理建议
- 参数校验错误返回明确字段提示
- 业务冲突返回 409
- 数据不存在返回 404
- 系统异常统一返回 500，并记录日志
