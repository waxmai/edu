# edu-schedule-system 最终验收报告

## 1. 结论

当前版本已经达到：
- **可用于受控环境正式试运行**
- **可用于小规模真实业务使用**
- **不建议在没有额外运维与安全治理的前提下直接大范围公网公开推广**

换句话说：
- 作为内测版、试运行版、单机构受控部署版，已经基本具备交付条件。
- 作为“完全放开公网、面向不特定用户、长期稳定商用”的正式版本，还存在少量高阶治理项未补齐。

## 2. 本轮验收范围

本次验收覆盖：
- 后端业务一致性
- 鉴权与登录安全
- 用户与权限治理
- 审计日志

- 备份恢复脚本

## 5. 当前剩余风险

### 5.1 非阻断但建议继续优化
1. **refresh token 仍是最小实现**
   - 已具备 rotation
   - 但还没有设备级会话管理、会话列表、主动踢设备能力

2. **权限仍是“角色级”而非“权限点级”**
   - 当前适合中小规模受控场景
   - 更复杂组织权限仍需继续演进

3. **恢复链路已具备受控商用试运行能力，但仍是第一阶段实现**
   - 当前已有 SMTP 发送、失败分类、有限重试、失败告警落盘、失败后 challenge 自动过期、平台可查 recovery alerts
   - 但还没有 provider 聚合、趋势统计、集中告警平台接入与更丰富的外部通道

4. **仍有少量页面与提示文案可继续产品化**
   - 部分接口错误文案仍偏技术化
   - 少量页面仍保留局部 ID 口径
   - 更适合在正式公网推广前继续统一收口

5. **smoke-e2e 仍依赖当前环境账号状态**
   - 脚本入口与使用文档已补齐
   - 但它仍不是数据准备器，默认依赖种子账号或显式传入当前有效 token / 密码
   - 若后续要进一步降低验收门槛，可再补最小可测数据准备能力

### 5.2 阻止“直接大规模公网放开”的因素
以下几项决定了当前版本仍不建议直接毫无保护地大范围公网推广：
- 设备级安全会话治理不足
- 权限点体系还不够细
- 运维体系仍偏“可控交付”而非“重度商用平台级”

## 6. 发布建议

### 6.1 建议允许的发布方式
建议：
- 单机构部署
- 固定账号制
- 管理员初始化后人工分发账号
- 受控人数的小规模试运行
- 联调/验收/试点学校或培训机构场景

### 6.2 暂不建议的发布方式
暂不建议：
- 完全开放公网注册
- 面向不特定用户的大范围公开推广
- 缺少专门运维值守情况下直接承接大规模生产流量
