# 前端性能收口记录

## 当前状态

前端构建已经稳定，但仍存在以下典型问题：

- `vendor-element-plus` 体积偏大
- 会出现 `vendor-vue-core` / `vendor-lodash` 空 chunk
- 仍有进一步的路由级拆分空间

## 当前建议

### P1.1，先处理空 chunk
优先检查 Vite 手工分包配置，避免把实际未进入 chunk 的库预先拆成固定 vendor 分片，造成空 chunk 输出。

### P1.2，再处理大 vendor
把 element-plus 的使用按更细粒度分析：
- 表格
- datetime picker
- icons
- 通用 vendor

目标不是过度优化，而是让主入口和常用页首屏成本更稳。

### P1.3，大数据量场景验证
建议专门验证以下页面：
- 平台租户页
- 平台校区页
- 平台审计日志页
- 恢复失败告警页
- 用户列表页

关注点：
- 首次渲染耗时
- 筛选交互延迟
- 分页切换耗时
- 大量 tag/表格列下的绘制成本

## 当前结论

前端性能已从“可用”进入“可交付”，但还没到“深度收口”阶段。
